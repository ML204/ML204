<Section label="What is it?">

**Batch gradient descent** computes the gradient using all training examples before taking one step. **Stochastic gradient descent (SGD)** takes a step after every single example, using an approximate gradient. **Mini-batch gradient descent** is the middle ground — a small random sample of examples per step.

In practice, almost all modern ML uses mini-batch gradient descent and simply calls it "SGD".

</Section>

<Section label="Why we need it">

If your dataset has 10 million examples, computing the full gradient takes 10 million forward passes before you can update the parameters even once.

That is too slow. You would update the model once per hour instead of thousands of times per second.

SGD fixes this by approximating the gradient using a small random subset — a **mini-batch** of, say, 32 or 256 examples. The approximation is noisy, but it is good enough and far faster.

</Section>

<Divider />

<Section label="Explained in detail">

**Batch gradient descent:**

$$
w \leftarrow w - \alpha \cdot \frac{1}{n}\sum_{i=1}^{n} \nabla L_i(w)
$$

One step uses all $n$ examples. The gradient is exact and smooth, but each step is expensive.

**Stochastic gradient descent (true SGD):**

$$
w \leftarrow w - \alpha \cdot \nabla L_i(w) \quad \text{for a single random } i
$$

One step uses one random example. Very fast, but the gradient is very noisy — the path zigzags.

**Mini-batch gradient descent (what everyone calls SGD):**

$$
w \leftarrow w - \alpha \cdot \frac{1}{b}\sum_{i \in \mathcal{B}} \nabla L_i(w)
$$

One step uses a random batch of $b$ examples (usually 32–512). The gradient is a good approximation, the path is moderately noisy, and the hardware (GPU) runs efficiently.

<Analogy>
  Batch GD is like asking every student in a school of 10 000 what they think before making one decision. SGD is like asking one random student and acting immediately. Mini-batch is like asking a class of 32 — fast, representative, and practical.
</Analogy>

**Why does noise help?**

Surprisingly, the noise in SGD is often *useful*. It helps the optimizer escape sharp local minima and find flatter, more generalizable solutions. Pure batch gradient descent can get stuck in a sharp minimum that happens to fit the training data but fails on new data.

</Section>

- **Press Play** on both paths. The **blue path (Batch GD)** moves smoothly and directly. The **orange path (SGD)** zigzags because each step uses noisy gradient estimates.
- Use the **Batch size** slider: larger batch → smoother path, closer to Batch GD. Smaller batch → more noise.

<Callout kind="tip">
  **Batch size 32–256** is the most common range. Larger batches give smoother gradients but need more memory and can generalize worse. Smaller batches are noisier but can generalize better and use less memory.
</Callout>

<Callout kind="info">
  One **epoch** = every training example has been seen once. With 10 000 examples and batch size 100, one epoch = 100 gradient steps.
</Callout>

<Callout kind="warning">
  **Common mistake:** using batch size 1 (true SGD) for a large dataset — it is noisy and slow on modern GPUs which are optimized for parallel computation on batches.
</Callout>
