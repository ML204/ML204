<Section label="What is it?">

Python provides two complementary paradigms for sequence processing:
- **Comprehensions**: Compact declarative syntax for mapping, filtering, and constructing new collections (**lists**, **dictionaries**, **sets**) in a single, highly optimized C-level loop.
- **Generators**: Stateful, resumable iterators that produce elements **lazily on-demand** using the `yield` statement or generator expressions (`(...)`), operating in $O(1)$ auxiliary RAM regardless of sequence length.

### Motivating Benchmark: Eager List vs Lazy Generator
When training deep neural networks on datasets containing millions of samples, loading everything into memory at once causes Out-Of-Memory (OOM) crashes:

```python
import sys

# An eager list allocates all 10,000,000 integers in heap memory upfront:
eager_list = [x for x in range(10_000_000)]
print(f"List RAM Footprint: {sys.getsizeof(eager_list) / (1024 * 1024):.2f} MB")
# Output: ~80.00 MB (plus overhead of pointed objects!)

# A lazy generator expression allocates only the iterator state object:
lazy_gen = (x for x in range(10_000_000))
print(f"Generator RAM Footprint: {sys.getsizeof(lazy_gen)} Bytes")
# Output: ~104 Bytes (constant O(1) memory!)
```

</Section>

<Section label="Why we need it">

In machine learning and big data pipelines:
- **Out-of-Core Processing**: A machine learning dataset might be 500 GB, but system RAM is only 16 GB. Generators stream chunks from disk directly into GPUs without loading the full dataset into memory.
- **Fast Feature Engineering**: List and dictionary comprehensions execute up to 35% faster than explicit `for` loops and `.append()` calls because bytecode execution runs inside CPython's optimized C loop.
- **PyTorch & TensorFlow DataLoaders**: Under the hood, modern batch collators and worker threads use the generator protocol (`__next__` and `StopIteration`) to pipeline batch loading asynchronously while GPU forward passes execute.

</Section>

### 1. The Anatomy of Comprehensions

#### List Comprehensions
The standard syntax follows:
$$
[\text{expression} \quad \text{for} \quad \text{item} \quad \text{in} \quad \text{iterable} \quad \text{if} \quad \text{condition}]
$$

```python
# Cleaning text tokens for a Natural Language Processing model:
raw_tokens = ["  Neural  ", "Net", "AI", " ", "transformers ", "nlp"]

clean_tokens = [t.strip().lower() for t in raw_tokens if len(t.strip()) > 2]
print(clean_tokens)  # ['neural', 'net', 'transformers', 'nlp']
```

#### Conditional Transformation vs Conditional Filtering
Pay close attention to where the `if` clause is placed:
1. **Filtering (trailing `if`)**: Keeps only elements matching the condition:
   ```python
   positives = [x for x in numbers if x > 0]
   ```
2. **Transformation (ternary `if-else` before `for`)**: Transforms every element conditionally:
   ```python
   # ReLU activation: f(x) = x if x > 0 else 0
   relu_activations = [x if x > 0 else 0.0 for x in activations]
   ```

#### Dictionary and Set Comprehensions
```python
# Inverted vocabulary index: mapping words to unique token IDs
vocab = ["<pad>", "<unk>", "learning", "rate", "loss"]
word2idx = {word: idx for idx, word in enumerate(vocab)}
print(word2idx)
# {'<pad>': 0, '<unk>': 1, 'learning': 2, 'rate': 3, 'loss': 4}

# Unique file extensions across a training folder:
file_names = ["img_1.jpg", "img_2.png", "img_3.jpg", "audio.wav"]
extensions = {name.split(".")[-1] for name in file_names}
print(extensions)  # {'jpg', 'png', 'wav'}
```

#### Nested Comprehensions: Flattening Matrices
Comprehensions can flatten 2D matrices into 1D feature arrays:

```python
matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
]

# Nested comprehension order mirrors standard nested loops:
# for row in matrix:
#     for val in row:
#         yield val
flattened = [val for row in matrix for val in row]
print(flattened)  # [1, 2, 3, 4, 5, 6, 7, 8, 9]
```

<Analogy>
  Think of a list comprehension as an assembly line worker putting pre-ordered parts into a fixed storage crate. A generator is a conveyor belt that sends each part down the line only when the next worker reaches out their hand.
</Analogy>

### 2. Generator Functions and the `yield` Keyword

When a function contains the `yield` keyword, Python compiles it into a **generator function**. Calling the function does not run the code; it returns a generator object implementing the **iterator protocol**:

```python
def count_down(n):
    print("Starting generator...")
    while n > 0:
        yield n
        n -= 1
    print("Generator exhausted.")

gen = count_down(3)
print(type(gen))  # <class 'generator'>
```

#### The Iterator Protocol Under the Hood
Each call to `next(gen)` resumes the function execution from the exact line where it paused at `yield`:

```python
print(next(gen))  # Prints "Starting generator..." then yields 3
print(next(gen))  # Resumes, decrements, yields 2
print(next(gen))  # Resumes, decrements, yields 1
# print(next(gen)) # Raises StopIteration and prints "Generator exhausted."
```

When used in a `for` loop, Python automatically catches `StopIteration` and terminates the loop cleanly:

```python
for val in count_down(3):
    print("Received:", val)
```

### 3. Practical ML Pipeline: Streaming Large Datasets

Here is how real-world machine learning data loaders feed mini-batches without saturating RAM:

```python
import random

def batch_streamer(file_paths, batch_size=32):
    """
    Streams samples from disk, batches them, and yields them to the trainer.
    Consumes minimal RAM even if file_paths contains 1,000,000 files!
    """
    batch_features = []
    batch_labels = []

    for path in file_paths:
        # Simulate reading sample from disk
        feature, label = [0.5, -1.2, 3.4], 1

        batch_features.append(feature)
        batch_labels.append(label)

        if len(batch_features) == batch_size:
            yield batch_features, batch_labels
            batch_features = []
            batch_labels = []

    # Yield remaining samples if dataset length is not divisible by batch_size
    if batch_features:
        yield batch_features, batch_labels
```

### 4. Advanced Generator Mechanics: `yield from`

The `yield from` expression delegates generation to another sub-generator or iterable, cleanly nesting data streaming pipelines:

```python
def stream_dataset_splits(train_files, val_files):
    print("Streaming training split:")
    yield from (f"Train: {f}" for f in train_files)

    print("Streaming validation split:")
    yield from (f"Val: {f}" for f in val_files)

dataset = stream_dataset_splits(["t1.csv", "t2.csv"], ["v1.csv"])
for item in dataset:
    print(" ", item)
```

#### Two-Way Generator Communication (`.send()`)
Generators can also receive data from the caller using `gen.send(value)`, turning them into **coroutines**:

```python
def running_average():
    """Calculates cumulative moving average of incoming training loss."""
    total = 0.0
    count = 0
    average = None
    while True:
        # Pauses and yields current average, then receives new sample
        val = yield average
        if val is None:
            break
        total += val
        count += 1
        average = total / count

avg_tracker = running_average()
next(avg_tracker)  # Prime the generator to the first yield (returns None)

print("Batch 1 avg:", avg_tracker.send(10.0))  # 10.0
print("Batch 2 avg:", avg_tracker.send(20.0))  # 15.0
print("Batch 3 avg:", avg_tracker.send(30.0))  # 20.0
```
